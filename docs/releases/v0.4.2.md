# CairnKV v0.4.2 — Replication Pipelining

Write throughput is no longer limited by the leader's serial broadcast:
per-peer in-flight windows and a group-commit WAL raise cluster Put by ~16×.

## Highlights

- WAL fsync moved off the Raft core thread into a dedicated group-commit
  thread; `commit_index` is bounded by `last_synced_index`.
- Replication is now state-driven: `next_index` advances optimistically on
  send, `match_index` only on confirmed responses, at most 4 in-flight
  batches per follower.
- `PeerClient` splits send and receive into separate threads; `Send()`
  reports a full queue instead of silently dropping the oldest message.
- Timed-out batches are retried after rewinding to `match_index + 1`;
  rejected batches clear the whole in-flight window.
- `examples/basic.cc` (libcairnkv walkthrough) and `docs/case-study-w4.md`.

## Correctness

- A leader never commits an entry before its own WAL has fsynced.
- A failed WAL fsync rejects new proposals and fails all pending promises.
- Heartbeats are sent only when the window has room; in-flight data batches
  also refresh the follower's election timer.
- Data race on `EventLoop::thread_id_` removed (found by TSan).

## Validation

- Build: 54/54; `ctest`: 7/7.
- TSan (`halt_on_error=1`): ctest, cluster-smoke, 5s benchmark — zero reports.
- ASan+UBSan: ctest, 5s benchmark — zero reports.
- Cluster Put 8t/32t: 114/125 → 1894/1901 ops/s; p99 132/452 ms → 6.5/20.9 ms.
- Single-node Put 8t/32t: 1532/1796 → 3574/3475 ops/s.

## Known limits

- Cluster throughput is about 53% of a single node: followers still fsync
  each AppendEntries on their core thread.
- Single-node throughput is capped by core processing on the 2 vCPU test
  VM (~3.5k ops/s).
- Stale reads still traverse the Raft core queue.
